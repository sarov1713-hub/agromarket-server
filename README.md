# АгроМаркет API

Backend лабораторных №6 и №7: Express 5, PostgreSQL, параметризованные SQL-запросы.
Это отдельный npm- и Git-проект внутри frontend. React поддерживает регистрацию, вход и добавление товаров администратором.

## Запуск

Для текущего компьютера база `agromarket` на DB01 уже создана, а рабочий
`DATABASE_URL` находится в `.env`. Повторно создавать базу или менять пароль не нужно.

```powershell
cd D:\agromarket-react\agromarket-server
npm install
npm run dev
```

API: http://localhost:3000. Проверка подключения: http://localhost:3000/api/health.
Ожидается JSON с `status: "ok"`, `db: "connected"` и `time`.

На новом компьютере: обеспечить доступ к PostgreSQL, создать базу `agromarket`,
скопировать [.env.example](./.env.example) в `.env` и указать рабочий `DATABASE_URL`.
Не перезаписывать уже настроенный `.env` примером.

Первичная инициализация (в текущей базе уже выполнена):

```powershell
npm run db:init
```

**Повторный `db:init` удаляет таблицы orders, products и users со всеми данными**, затем
создаёт их заново создаёт администратора из переменных окружения и загружает четыре товара из [data/db.json](./data/db.json).
Все действия выполняются в транзакции: при ошибке изменения откатываются.
SERIAL выдаёт идентификаторы; единица товара берётся из окончания названия (`л`/`кг`).
Не запускать эту команду для обычного перезапуска сервера.

Frontend в другом терминале:

```powershell
cd D:\agromarket-react
npm run dev
```

Открыть http://localhost:5173. `CORS_ORIGIN` задаёт разрешённый origin, по умолчанию
это `http://localhost:5173`. `PORT` по умолчанию равен 3000. Для запуска без watch: `npm start`.

## Эндпоинты

| Метод | Путь | Доступ | Ответы |
|---|---|---|---|
| GET | /api/health | Все | 200, 500 |
| GET | /api/about | Все | 200 |
| GET | /api/products?search=мол | Все | 200, 400 |
| GET | /api/products/:id | Все | 200, 400, 404 |
| POST | /api/auth/register | Все | 201, 400, 409 |
| POST | /api/auth/login | Все | 200, 400, 401, 429 |
| GET | /api/auth/me | Bearer token | 200, 401, 404 |
| POST | /api/products | admin | 201, 400, 401, 403 |
| PUT | /api/products/:id | admin | 200, 400, 401, 403, 404 |
| DELETE | /api/products/:id | admin | 204, 400, 401, 403, 404 |
| GET | /api/orders | admin | 200, 401, 403 |
| POST | /api/orders | Все | 201, 400 |
| PATCH | /api/orders/:id | admin | 200, 400, 401, 403, 404 |

Неизвестные маршруты возвращают 404 JSON. Неожиданные ошибки и недоступность БД —
500 JSON без технических деталей. Некорректный JSON — 400, слишком большое тело — 413.

Товар: обязательны непустой `name` и целый `price >= 0` в диапазоне PostgreSQL INTEGER.
Необязательные поля: `category`, `image`, `unit` (по умолчанию `кг`).
PUT заменяет все редактируемые поля: пропущенные `category`/`image` становятся null,
`unit` — `кг`. Поля `id` и `created_at` сохраняются.

Заявка: обязательны `name`, `email`, целый `quantity >= 10`.
Принимаются также `product_id`, `phone`, `date`, `comment`.
Поле формы `date` сохраняется в `delivery_date` и возвращается строкой YYYY-MM-DD.
Пустые необязательные значения сохраняются как null. Статус при создании — `new`.
PATCH принимает `{ "status": "processing" }`. Допустимые статусы контролирует CHECK:
`new`, `processing`, `done`, `cancelled`.

## Проверки

Автоматические интеграционные проверки на реальной БД:

```powershell
npm test
```

Требуется доступная и инициализированная база из `.env` и свободные порты 3106 и 3107.
Тест запускает собственный Express, проверяет CRUD, валидацию, SQL-ограничения,
поиск, некорректный JSON, перезапускает Express и проверяет сохранение товара/заявки.
После удаления товара проверяет `ON DELETE SET NULL`. Удаляет только собственные
тестовые записи; `db:init` не запускает.

Postman: импортировать [коллекцию v2.1](./postman/agromarket.postman_collection.json)
и запустить все 18 запросов через Collection Runner по порядку.
Переменная `baseUrl` уже задана: `http://localhost:3000/api`.
`productId` и `orderId` заполняются ответами автоматически при каждом запуске.
Каждый запрос проверяет HTTP-статус; дополнительные проверки проверяют поля ответов.
Повторный прогон не требует ручного изменения id. Каждый прогон создаёт нового пользователя и оставляет тестовую
заявку со статусом processing, а созданный товар удаляет.

Альтернатива Postman при запущенном API:

```powershell
npx --yes newman run postman/agromarket.postman_collection.json
```

## Переменные окружения (.env)

Существующий DATABASE_URL сохранён. Для ЛР7 добавлены:

| Переменная | Назначение |
|---|---|
| JWT_SECRET | Случайный секрет подписи JWT (32 байта, 64 hex-символа); не публиковать |
| JWT_EXPIRES_IN | Срок действия токена, по умолчанию 2h |
| ADMIN_EMAIL | Email администратора, создаваемого seed |
| ADMIN_PASSWORD | Пароль для первоначального bcrypt-хэширования в seed |

Реальные значения находятся только в локальном .env. В [.env.example](./.env.example)
для секретов используются заглушки. При отсутствии JWT_SECRET сервер завершает запуск.
Секрет нельзя передавать frontend или вставлять в онлайн-декодеры JWT.

## Авторизация ЛР7

Регистрация принимает name, email, password. Email нормализуется trim + lowercase,
пароль — минимум 8 символов, максимум 72 байта (ограничение bcrypt).
Роль всегда user, даже если клиент присылает role=admin. Пароли хранятся как
bcrypt hash с cost 10. JWT содержит sub и role, а также стандартные iat/exp.
В ответах register/login/me нет password_hash.

Для защищённых запросов используется Authorization: Bearer <token>.
POST/PUT/DELETE products и GET/PATCH orders доступны только admin.
POST orders остаётся публичным; user_id добавлен в схему, но для публичных заявок
остаётся null. Бонусный optionalAuth не реализован.

Login: пять неуспешных запросов за 15 минут на IP, следующий возвращает 429.
Успешные входы не учитываются. Счётчик хранится в памяти и сбрасывается при
перезапуске Express. RateLimit и Retry-After позволяют узнать состояние ограничения.
Helmet включён перед CORS; JSON ограничен 10kb. Ошибки JSON возвращаются как JSON.

Frontend хранит только token и безопасный user в localStorage. При запуске проверяет
/auth/me. При 401 с сохранённым токеном очищает оба значения и перезагружает страницу.
Logout также очищает их. localStorage выбран по заданию; его доступность JavaScript
означает, что защита от XSS важна. Скрытие формы администратора дополняет серверные права.

Postman использует Bearer {{token}} на уровне коллекции. Сразу после Health выполняется
вход администратора. Регистрация и вход имеют No Auth, user-проверки используют
{{userToken}}. В коллекции указан учебный пароль из задания; это не JWT_SECRET.
Если ADMIN_PASSWORD изменён, обновить локальное значение adminPassword в Postman.
Email регистрации содержит timestamp и guid, поэтому повторный прогон не конфликтует.

## Лабораторная 7 — ответы

- Два зарегистрированных пользователя с одним паролем получили разные bcrypt-хэши.
  Оба прошли bcrypt.compare: bcrypt генерирует случайную соль для каждого хэша.
- Регистрация с role=admin вернула 201 и role=user. Клиентское поле role игнорируется.
- Payload JWT изменён локально с user на admin без пересчёта подписи: сервер вернул
  401 «Недействительный токен». jwt.verify проверяет подпись; jwt.io не использовался,
  реальные токены и секрет не отправлялись на сторонние сайты.
- После порчи token в localStorage и обновления страницы /auth/me вернул 401,
  token/user удалились, появилась форма входа, форма администратора исчезла.
- Скрыть кнопку недостаточно: запрос можно отправить вручную. Такой fetch из браузера
  с user-токеном проверен и получил 403. Без токена защищённые маршруты возвращают 401.
- ИИ использовался для расширения существующего проекта, SQL-схемы, bcrypt/JWT,
  middleware прав, форм React, автотестов, Postman и этой документации.

## Лабораторная 6 — ответы

- `price = -5`: API возвращает 400, поле price должно быть целым числом >= 0.
  Прямой INSERT в PostgreSQL отклоняется CHECK с кодом `23514`.
- Отсутствует `name`: API возвращает 400 «Поле name обязательно».
  Прямой INSERT без name отклоняется NOT NULL с кодом `23502`.
- `product_id = 9999`, если такого товара нет: внешний ключ вызывает `23503`,
  обработчик возвращает 400 «Связанная запись не найдена».
- SQL-инъекция: при конкатенации ввод мог бы стать частью SQL-условия.
  При `WHERE name ILIKE $1` и параметре `%${search}%` ввод является значением.
  Строка `' OR 1=1 --` проверена на безопасном API: вернулся пустой массив,
  все товары не раскрылись. Уязвимый вариант не устанавливался и не запускался;
  поведение «до» описано теоретически. Символы `%` и `_` сохраняют семантику ILIKE.
- Двойная защита quantity: JS отклоняет некорректное число и объём меньше 10 кг;
  CHECK в БД защищает от обхода API. Прямой INSERT quantity=5 проверен: `23514`.
- После удаления товара заявка осталась, `product_id` и `product_name` стали null.
  Это результат ON DELETE SET NULL и LEFT JOIN.
- Статус `lost`: список в JS не проверяется; CHECK выдаёт `23514`, API — 400.
- ИИ использовался для анализа прошлой лабораторной, реализации SQL-схемы,
  seed, CRUD, обработки ошибок, тестов, коллекции Postman и документации.

## Лабораторная 5 — ответы

- `res.send()` может возвращать текст, `res.json()` возвращает JSON с соответствующим Content-Type.
- Без `next()` middleware не передаёт запрос дальше по цепочке.
- Логгер после маршрутов не увидит запросы, обработанные раньше.

## Git и настройки

`.env` и `node_modules` исключены из Git; `.env.example` содержит только пример пароля.
Строка подключения не печатается в логах. Все пользовательские значения в SQL
передаются параметрами. Коммит и push автоматически не выполнялись.
Команды выполнять именно в отдельном backend-репозитории:

```powershell
cd D:\agromarket-react\agromarket-server
git status
git add .
git commit -m "lab7: users, bcrypt, JWT auth, roles, rate limit, helmet"
```

Push выполняется владельцем проекта после проверки.

Frontend коммитится отдельно из D:\agromarket-react. Добавлять только изменённые файлы src,
не вложенные backend/старые проекты:

```powershell
git add src/api.js src/App.jsx src/layout.css src/components/LoginForm.jsx src/components/AddProductForm.jsx src/components/ContactForm.jsx src/components/ProductCard.jsx
git commit -m "lab7: login/register form, apiFetch with token, admin product form"
```
